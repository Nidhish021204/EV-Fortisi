# VOLTGRID — EV charging infrastructure siting for New York City

A 19-stage pipeline that reads **13.5 GB** of municipal mobility, traffic and land-use records and produces a costed, constraint-satisfying list of new EV charging sites — plus a dashboard built for defending that list in a public hearing.

The output for a 120-site programme: **642 ports, $28.9M, 29.3% of unmet demand served, 7.0 min mean queue wait**, on a plan that respects Con Edison's published per-feeder charging capacity and a per-borough accessibility floor.

![VOLTGRID dashboard — the H3 demand surface for New York City, with recommended sites marked in red, the optimality certificate and per-feature attribution in the right rail](docs/dashboard.png)

*Live at [ev-fortisi.vercel.app](https://ev-fortisi.vercel.app). The field is the measured unmet-demand surface across 8,740 H3 cells; red crosshairs are the 120 recommended sites. Every number on screen is regenerated by the pipeline — nothing is mocked.*

---

## Why not just classify each cell?

The obvious approach — label every map cell "station / no station" and fit a classifier — fails four ways, and each failure shaped the architecture:

| Problem | Why it breaks | What this project does |
|---|---|---|
| **Circularity** | Existing stations encode where operators *already* built. Maximising accuracy against them maximises conformity to the status quo and can never justify a new area. | Demand is measured independently — 47.4M taxi trips for within-zone shape, 1.65B for-hire trips for current zone magnitudes, plus traffic counts — in physical units (kWh/day). |
| **Positive-Unlabeled** | A cell without a charger is *unbuilt*, not unsuitable. Treating unlabeled as negative destroys calibration. | Bagged PU learning (Mordelet–Vert) with Elkan–Noto calibration. |
| **Spatial leakage** | Adjacent cells share features, so random k-fold inflates scores badly. | Spatial block CV, reported *next to* naive k-fold so the inflation is visible (+0.49 R²). |
| **Ranking ≠ planning** | The top-k cells cluster and cover the same demand repeatedly. | Capacitated maximal-covering optimisation over a *set*, with M/M/c queueing. |

So the model is a four-stage cascade: **demand → suitability → gap → allocation**.

## Results

Validation is deliberately unflattering. The headline is a **temporal forward test** — fit on the network as it stood at 2018-12-31 (219 positive cells), then check whether the model predicted where the 2019–21 build-out actually landed (190 of 8,522 candidates, a 2.2% base rate).

| Method | PR-AUC | P@100 | Lift |
|---|---|---|---|
| **PU model** | **0.170** | **35.0%** | **15.7×** |
| Distance to nearest station | 0.099 | 19.0% | 8.5× |
| Demand ranking | 0.097 | 23.0% | 10.3× |
| Traffic ranking | 0.058 | 9.0% | 4.0× |
| Random | 0.021 | 1.0% | 0.4× |

PR-AUC rather than ROC-AUC: at a 2.2% base rate ROC-AUC is dominated by the negative mass and flatters everything.

**Greedy allocation is certified at 97.9% of a CBC-proved optimum** (288,139 vs 294,252 kWh/day), far above its (1 − 1/e) ≈ 63.2% worst-case guarantee — which is what licenses using greedy behind the dashboard's live budget slider while the MILP serves as the audit path.

## Findings, including the ones that went against me

**Land use is what makes demand predictable.** On traffic features alone the demand model captured 22.4% of true energy in its top decile — *losing* to a trivial AADT ranking at 49.0%. Adding PLUTO built-environment features took it to **78.8%** against a 90.0% oracle ceiling. Parking floor area and assessed value density lead the SHAP attribution: whether there is physically anywhere to put the hardware is among the strongest predictors of where a charger actually got built.

**Siting does not transfer into NYC.** Cross-domain tests across Germany, German metros, NYC and Connecticut show that adding globally-consistent built form lifts transfers beating their target baseline from **5/12 to 9/12** — so network *shape* alone doesn't transfer, but built form largely does. The exception is absolute: **every transfer into NYC fails**, and Germany → NYC got *worse* with built form. NYC has the strongest trivial baseline of any domain. Do not pretrain elsewhere and deploy here.

**The grid constraint was reading the wrong column, and I was 3.2× too permissive.** The pipeline derived headroom from the substation bank rating minus peak. Con Edison publishes something better in the same layer: `STORAGE_MAX_CHARGE`, a **per-feeder** limit on new charging load that varies within a bank — four feeders on one WASHINGTON STREET bank allow 0.138, 0.209, 1.345 and 4.244 MW against a single 62 MW bank headroom. City-wide that is **533 MW, not 1,686 MW**, and 22.8% of feeders publish zero. Correcting it raised the grid's cost from 0.01–0.49% of served energy to **1.78%** (2.42% by k=300) and cut the reachable programme from 338 sites to 308. "The grid is not the bottleneck" survives in direction but was wrong in magnitude.

**Manhattan's missing grid data is now explained rather than filled.** Con Edison *does* publish capacity for the secondary network — but it is **generation** hosting capacity for DER interconnection, not charging load headroom, so substituting it would be a category error. Instead every cell is labelled by why it lacks data. Weighted by built floor area: 38.5% has enforced feeder capacity, 59.4% sits on the secondary network, and only **2.1% is genuinely unaccounted**. Cell counts alone said 62.5% covered — flattering, because rivers and parks count as cells.

**Yellow taxi put 72% of the city's demand in Manhattan. The current for-hire fleet says 37%.** The surface was built on 2015–16 yellow taxi, the only NYC release with coordinates. High-volume for-hire trips are now 84.8% of drop-offs, and re-weighting demand to Q1 2026 zone shares moves Manhattan 72.1% → **36.5%**, with Queens +12.4, Brooklyn +12.5 and the Bronx +9.3 points. The Manhattan bias this README already admitted to was far larger than "biased sample" suggests.

**14 of 120 sites exist only because of the equity floor** — and the previous figure of 26 was wrong. That counterfactual re-ran the optimiser without the floor but never merged the grid, so every site the grid displaced was miscounted as equity-forced. The counterfactual now differs from the real plan in exactly one respect.

**Metrics are quoted at the precision they support.** A 15-seed sweep puts PR-AUC at 0.170 ± 0.0029 (95% CI 0.166–0.174) and shows lift supports only **one** decimal — so "15.70×" would be false precision. That same interval doubles as the drift-detection control limit: inside it is noise, outside is worth a human.

**56 of 120 sites are selected in every one of 200 bootstrap replicates; 3 are coin-flips.** A ranked list hides that distinction entirely. The plan is *less* stable than before Stage 8, which had 77 always-selected — and that is the honest consequence of a flatter demand surface: once demand is no longer overwhelmingly concentrated in Manhattan, many more cells are genuinely competitive and the choice between them is less decisive.

## Data

| Source | Role | Volume |
|---|---|---|
| AFDC alternative fuel stations | labels + temporal validator (`Open Date` 99.86% populated) | 50,289 rows |
| NYC Yellow Taxi 2015-01, 2016-01…03 | demand signal — within-zone *shape* (only NYC release with lat/lon) | ~47.4M trips, 7.4 GB |
| TLC zone/industry monthly aggregate | current cross-zone *magnitude*, 2019-01…2026-07 | 1.65B HVFHV + 333M yellow trips |
| TLC HVFHV / yellow / green, Q1 2026 | per-zone mean trip miles (the aggregate has no miles) | 73.7M trips, 1.6 GB |
| NYC Automated Traffic Volume Counts | throughput + congestion | 14,359 segments, 3.3 GB |
| NYC MapPLUTO | built environment | 858,284 tax lots |
| ACS B25044 | vehicle availability | tract-level, allocated by residential units |
| Con Edison EV/storage capacity | **per-feeder charging limit**, bank headroom, no-charge feeders, network-area boundary | 624 feeders · 528 no-charge · 84 polygons |
| JRC GHSL | globally-consistent built form, for transfer | ~90 m raster |
| BNetzA (Germany), AFDC-CT | transfer domains | 36,770 / 533 stations |

The five Kaggle-sourced datasets are expected under `data/raw/` (see [PLAN.md](PLAN.md) for the exact layout); the rest are fetched and cached automatically on first run. **`data/raw/` is gitignored** — 13.5 GB does not belong in version control.

## Running it

```bash
python run_pipeline.py                 # all 19 stages, ~45 min warm
python run_pipeline.py --only demand   # one stage
python run_pipeline.py --from features # from a stage onward
```

`certify` dominates the runtime — the MILP now carries both the per-feeder and the bank capacity families (249 grid constraints) and CBC takes ~18 min to prove optimality.

Dashboard:

```bash
cd dashboard && npm install && npm run dev
```

Requires Python 3.13 with `duckdb h3 lightgbm pulp pandas numpy scikit-learn pyarrow shapely pyproj rasterio`, and Node 20.

The first run downloads ~1 GB of GHSL raster tiles and takes ~3 h; every run after is ~23 min against the OS page cache.

## Layout

```
src/evopt/
  ingest/     stations · mobility · rideshare · traffic · landuse · acs · ghsl · feeders
  models/     demand · suitability · allocate · certify · explain · uncertainty · transfer
  features.py surface.py geo.py export.py drift.py
dashboard/    Vite + React + TypeScript, custom canvas H3 renderer
reports/      every metric this README quotes, regenerated each run
scripts/      check_reports.py — asserts PLAN.md matches reports/
```

The dashboard renders its own vector geometry: **no tile server, no basemap, and no third-party request of any kind** — fonts are self-hosted, and CI fails the build if an external URL appears in `dist/`. It is meant to run on an isolated operations-room machine.

## Limitations

- **Within-zone demand shape is still 2015–16.** HVFHV records carry only taxi-zone IDs, no coordinates, so the current-era correction re-weights 263 zones — it cannot see activity moving from one corner of a zone to another after 2016.
- 12.68% of current VMT is drop-offs TLC cannot place to any zone (codes 264/265). Those are excluded from the re-weighting rather than redistributed.
- **The grid constraint binds unevenly.** It applies only where Con Edison publishes feeder capacity — 38.5% of built floor area — so Manhattan, entirely secondary network, competes unconstrained against boroughs that are constrained.
- Cost is a flat $45k/port. Real siting cost is dominated by electrical service upgrades and varies by an order of magnitude.
- No parcel-level feasibility: a recommended cell is 0.105 km², and whether a specific lot inside it is available, zoned and connectable is out of scope.
- **The model is NYC-specific.** Nothing transfers in. Refit before using it anywhere else.
